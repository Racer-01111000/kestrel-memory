# Kestrel Memory House

This directory tree is the human-readable memory house for Kestrel continuity.

The purpose is to preserve identity, doctrine, project state, evidence, timeline, and active work in a form a human can read first.

Machine-ingest files may shadow this structure, but they do not replace it.

---

## Reading order

If you need to orient quickly, read in this order:

1. `README.md`
2. `MEMORY.md`
3. `SOUL.md`
4. `IDENTITY.md`
5. `USER.md`
6. `CONTINUITY_POLICY.md`
7. `TRUST_MODEL.md`
8. relevant project folder
9. `runtime/active_context.md`

This follows the human order of orientation:
- map
- memory
- self
- relationship
- rules
- mission
- present moment

## Update workflow

Safe default workflow:

1. write or update markdown source
2. classify the material
3. add changelog or handoff note if needed
4. only then generate ingest chunks/manifests
5. promote to canonical only when justified

---

## Protection model

Protected files are high-impact files governing identity and doctrine.

Major rewrites to protected files require explicit Rick approval.
Minor maintenance edits may be allowed under continuity policy if conservative, logged, and non-destructive.

Approved control channels for real approval include Telegram DM and approved local control surfaces used by Rick.

---

## Operating rule

The memory house should stay readable by a human.
The indexed machine view must remain secondary.

When uncertain:
- preserve provenance
- classify conservatively
- avoid silent over-promotion
- leave a visible trail
